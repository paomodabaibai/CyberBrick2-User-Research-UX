# 转向异常：源码复核与最小整改建议

## 本轮范围与结论

只研究官方源码、最新本地代码，并用 PC 做纯数学复核。未连接串口、未上传、未驱动机器人，未修改运行代码。用户最新状态是正常 otto_session 已恢复，不再沿用“90°保持中”的旧交接。

最优先处理：转向符号不应同时改变髋振幅分配和前后行走相位。当前新增的 turn>0 踝翻转与 Otto 原版不符，并且数学上等价于切换前后行走方向。这是已确认的软件问题；是否解释全部实际偏航，仍需改后实机对照，不排除摩擦、负载和安装因素。

## 官方依据

https://github.com/OttoDIY/OttoDIYLib/blob/f384c00a641e11c8741487320c6f1d82ad72e6d5/src/Otto.cpp

本轮从官方 GitHub API 读取 main，对应 SHA 如上。Otto::turn 实现：

- LEFT：髋振幅 [30,10]；RIGHT：[10,30]。
- 两者踝振幅均 [20,20]，偏置均 [4,-4]。
- 两者相位均 [0,0,-90°,-90°]。
- walk 的前后方向通过踝相位 -90°/+90° 切换。
- turn 的头部文字注释与 LEFT 分支的大振幅侧表述有出入；本报告以实际分支赋值为准。物理左右仍需结合项目舵机映射确认。

原版是差幅弧线转向，不承诺像差速轮车那样零位移原地转。当前 session 的 drive=0 只是输入变量，不会消除两髋同相正幅振荡产生的平移。

## 当前代码里的确定问题

### 1. 转向顺便反转了行走相位

otto_oscillator.py：flip = pi if turn > 0 else 0。

前进 direction=+1 时：sin(phi-pi/2+pi) = sin(phi+pi/2)，和后退 direction=-1 的踝波形完全相同。PC 采样验证二者踝输出最大误差 0。

所以当前一边转向是“前进式差幅”，另一边变成“后退式反向差幅”。两项同时反转，可能得到相同物理偏航。这比“振幅不对称不起作用、踝主导一切”的结论更直接；现有观察无法分离两因素，不能宣称某一因素主导。

flip 在 turn=0 有不连续：scale=1、踝振幅20°时，跨过零点可造成最大40°的踝目标跳变（取决于当时相位）。当前 ramp 只渐变 scale，无法平滑这个相位开关。双杆略不一致也会触发它，不只影响单杆。

### 2. 全局 steer_trim 破坏了左右对称

实际参数 hip_amp=30、turn_split=25、steer_trim=0.2。
使用0.8杆量、scale=1计算：

| 输入 | drive | turn | 两髋振幅 | phase=0的两踝偏角 |
|---|---:|---:|---|---|
| 左杆前推 | 0 | -0.8 | 30/15 | -16/-24 |
| 右杆前推 | 0 | +0.8 | 5/30 | +24/+16 |
| 左杆后拉 | 0 | +0.8 | 5/30 | +24/+16 |
| 右杆后拉 | 0 | -0.8 | 30/15 | -16/-24 |

直行微调目前加入所有转向，正向饱和而负向减弱。故两侧甚至不是对称的振幅交换。先在诊断转向中把 steer_trim 置零，恢复30/10与10/30的官方对照基准（或在安全范围内同比缩小）。不要先追求30/5的强转。

### 3. 旧交接有逻辑错误

“前推左杆=-0.8、前推右杆=+0.8，因此符号只跟推拉走”不成立。_axes 确实区分左右杆。

同样起始相位/scale/板端版本下，左前与右后产生相同控制量，右前与左后也相同。因此“任意前推都同向、任意后拉都反向”不能被当前静态映射完整解释。若严格重复仍如此，需要核对实际原始杆量、板端版本、起始相位/接触状态，而不是强行让观察符合错误推论。

### 4. 当前一项测试锁定了错误假设

tests/test_otto_oscillator.py 中 test_ankle_lift_follows_the_big_stride_leg 要求正负转向的踝波形相反。这验证的是后加的假设，不是官方 turn 行为，不能用“测试全绿”证明它正确。

## 建议交给执行 Agent 的最小整改

1. 保留目前已经可行走的版本、关节标定、驱动与无线，不重写框架。
2. 取消由 turn 正负触发的踝 pi 翻转。踝相位只由明确的前进/后退模式决定；左右转共享相同踝波形。
3. 首轮转向对照关掉 steer_trim，采用原版振幅比30/10与10/30，踝20、偏置±4；先按实际有效限位验证整周期，超限应统一缩放，不逐点截断。不要根据陈旧注释判断限位。
4. 把单杆命令明确定义为左/右弧线，不再以 drive=0 声称零平移。先恢复两侧相反方向，再单独决定后拉单杆的产品语义。若要完全复现官方，左前对应LEFT、右前对应RIGHT；本项目 turn 的抽象正负不必与官方 dir 同号。
5. 用一处映射常量处理最终物理左右相反；不要为单独一边再翻踝相位。
6. 替换上述错误测试。新增全周期性质检查：左右转踝完全相同；零trim时两髋振幅互换；小转向跨零不使踝跳变；前后方向才改变踝相位；四组摇杆真值表；全周期限位。
7. 实机只做一对基准：相同地面/起姿、相同杆量、相同完整周期数，记录净偏航方向及大概角度、平移。先通过“方向相反”，再优化转弯半径。

若修正后仍转不动：观察支撑脚是否随身体滑、摆动脚是否持续拖地，以及带载髋实际幅度是否达到目标，再决定脚底摩擦/承重偏置/周期。不要直接全脚加防滑或继续增大角度；它们可能增加扭转阻力或掩盖波形问题。
