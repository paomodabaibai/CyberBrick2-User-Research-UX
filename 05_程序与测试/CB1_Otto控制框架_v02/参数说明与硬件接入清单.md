### 板载会话（`main_v02.py`）与显式使能

**默认不动作：收到有效遥控帧不会使能任何东西。** 使能/恢复入口**现场重读遥控**（不信任循环暂停前保存的旧输入），完整流程两选一：

```python
# A. 连续循环 + Ctrl-C 暂停（推荐操作流程）
import main_v02
main_v02.run()                 # 初始化 RcLink（rc_module）并持续读取；Ctrl-C 暂停（力矩保持）
main_v02.SESSION.enable()      # 暂停后从 REPL 显式使能：此刻重读遥控，无帧/K4按住 → 拒绝
main_v02.resume()              # 继续循环；两杆回中被观察到后才接受迈步
main_v02.SESSION.recover()     # 停止/失联后显式恢复（同样现场重读 + K4 门禁 + 回中）
main_v02.SESSION.release()     # 退出：关闭 PWM（舵机电源不会被软件切断）

# B. 分步调试（REPL 一拍一拍看）
s = main_v02.start(link=main_v02.RcLink())   # link 用关键字传入（第一个位置参数是 cfg）
s.poll()                       # 每次调用 = 读一帧 + 控制器走一拍
s.enable(); s.enable_debug(); s.recover(); s.release()
```

| 规则 | 行为 |
|---|---|
| 使能门禁 | 无有效帧或 K4 按住 → 拒绝使能并说明原因；K4 只停止，永不使能 |
| 回中武装 | 使能、恢复后触发器未武装：必须先观察到**两杆回中**才有迈步请求；上电摇杆已推不会即走 |
| 不自动续走 | 停止、失联、重连均不自动恢复；恢复后同样要重新回中 |
| 卡顿防护 | 单拍时间差 >`STALL_MS`(500ms)：走行中→FAULT（拒绝跳阶段/瞬移姿态），空闲→从当前时刻继续 |
| 新步计时 | 步态请求触发那一拍不把请求前的等待算进动作（首拍 gait 时间=0） |
| 计时回绕 | 板端 `time.ticks_ms/ticks_diff`；PC 端同语义 30 位回绕时钟（timeutil.py） |

**新鲜度局限（诚实记录，勿"修复"）**：`rc_slave_data()` 无序号、无收包时间戳，`REMOTE['timeout_ms']` 因此**无法真实应用**（现置 None），我们不伪造新鲜度：帧为 None 即断链，且**绝不**用"摇杆值不变"推断失联。旧缓存帧无法识别——这是官方接口限制，已记录在 config 注释与 input_adapter 文档串。

### 遥控按钮索引注意
`REMOTE['stop_button']=3` 是**按钮组内 0 基偏移**（K1=0…K4=3），`from_rc` 内部加按钮基址 6 得到全帧下标 9。不要按 v01 的全帧索引习惯直接填 9（曾因此越界，已被测试抓住）。

### 步态符号配置（未标定前的方向旋钮）
`GAIT['step_sign_left'/'step_sign_right'/'ankle_sign']`：镜像安装意味着电气符号≠空间方向，落地观察后**只改这三个数**，不改 planner。

## 2. 真机接入安全清单（按顺序执行，任何一步不满足就停）

1. **前置确认（沿用 v01 结论）**：
   - 接收板 `boot.py` 仍处于改名状态（`boot_official_disabled.py`），防止官方程序抢总线导致 S2 疯转。上电后先 `import os; os.listdir('/')` 确认。
   - S2 上仍是 360°舵机：v02 驱动层会跳过它，但**不要**手动给它发非 1500µs 脉宽；中位是否能真正停转仍未标定。
   - **左踝 180° PG001 到货前，不开完整步态**（三关节演示不代表步态）。
2. **确认 COM 与板子**：按 USB 序列号认板（`58:E6:C5:A8:1B:0C` = 接收板），重插后 COM 号会变。只允许 `resume` 方式连接，禁止软复位接收板。
3. **上传文件**（mput 到 `/`，逐个 SHA256 校验）：
   `config.py, joint_model.py, trajectory.py, gait_planner.py, input_adapter.py, command_mapper.py, states.py, controller.py, main_v02.py, bench_v02.py, drivers/__init__.py, drivers/cb1_pwm.py`。
   不要传 `simulator.py / run_demo.py / tests/ / sim_config.py`。台架操作顺序见《台架验证计划_v02.md》（阶段B先 diag/monitor，无 PWM 验证通过才允许动执行器）。
   运行：`mpremote connect COM7 run main_v02.py`（或放进 / 后 `import main_v02` + `main_v02.run()`）。**Ctrl-C = 暂停（力矩保持）**，session 存在 `main_v02.SESSION` 供 REPL 操作；**退出必须显式 `SESSION.release()`（关闭 PWM）**，这是有意的：暂停-使能-继续流程不能被自动停输出打断。注意"关闭 PWM"=停止脉冲信号，**不等于切断舵机电源**——电源由物理开关（巴掌断电开关）负责。
4. **改 `DRIVER='cb1_pwm'` 只在板上的 config.py 里改**（PC 侧保持 'sim'，测试不依赖机器）。
   驱动工厂会 `assert machine.Pin(10).value() == 0`——GPIO10 读不到 0 说明插的是发射板，直接拒绝启动。
5. **首次上电观察顺序**（全程托住机器人，巴掌断电在手边）：
   a. `enable()` → 四关节（实际三个会动，S2 跳过）应缓慢走到标称中位；有任何一步方向反了立即断电，改 `direction` 或 `trim`，**不要**靠改步态参数补偿安装方向。
   b. 逐关节 ±5° 标定 `trim`（可临时用 v01 的 `milk_bench.joint()` 思路，但注意它不屏蔽 S2，用前先改）。
   c. 定 LEFT_SIGN 与踝符号（v01 遗留）：小幅移重心观察重心是否真的移到支撑腿。
   d. 以上全部确认后，把实测值写回 `config.py`，才开始托住状态下的 `request_step('left')` 单步。

## 3. 已知边界（不要绕过）

- 超限是**拒绝整组动作**（LimitViolation），不是钳位；如果真机上频繁出现拒绝，说明标定或参数错，不是框架错。
- STOPPED 只是冻结当前姿态，**不保证站姿稳定**（可能在单脚相中途冻结）；要松开 outputs 用 `release_output()`。
- FAULT 后重连不会自动恢复，必须显式 `recover()`；`FAULT` 状态下 `enable()` 会抛异常，这是故意的。
- 同侧连续步在 v02 是**显式接口返回不支持**，不是 bug；实现时只改 `gait_planner.same_side_strategy`。
