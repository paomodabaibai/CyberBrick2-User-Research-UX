## 一、当天解决的三个根因（时间顺序）

### 1. 间歇性完全不动 = 旧电池电压临界
- 现象：同一代码上午能走、下午不走（供电接法相同）；软件日志 4 步全 done 但机械零反应。
- 排查链：单关节直写能动 → 四关节同时步态级摆动能动 → 完整步态不走 → 换新电池立即恢复。**电池在临界电压时逻辑电路正常（灯亮、USB 兜底），但舵机电源轨带不动连续负载。** 这同时解释了 9-24 上午 trace 日志"step done 但用户看不到动作"的悬案——遥控代码当时就是好的。
- **教训：展示前必须换全新电池。**

### 2. 链路时断时续 = 发射板插拔/供电闪断会中断 2.4G 会话
- 现象：enable 被拒"no valid frame"→ 几秒后探针 199/200 有帧 → 再跑又被拒；或 974 次读取 820 次 None。
- 根因：发射板插拔插头/换电池/接触闪断会打断 2.4G 链路，**彻底断电重启发射板后恢复**（388/389 帧）。发射板还有 auto-sleep，静置后动一下摇杆唤醒。
- 顺带修复：`walk_session.wait_for_frames()` 帧预热（等 10 帧连续有效再使能），避开 mpremote 软重启后 rc_slave_init 的冷启动窗口。
- **教训：现场"没反应"先跑 8 秒帧探针（ok/none 比例），链路死→重启发射板，别怀疑代码。**

### 3. 左摇杆卡在 +1.00 = 摇杆插头接触不良
- 现象：会话中左杆 raw 恒 3828 不变，右杆正常。mapper 因左杆永不回中而全部拦截。
- 修复：重插发射板摇杆插头恢复（与 S2/S3 舵机插头同类毛病，本项目插头普遍偏松）。

## 二、v03 操作模式（全部实机验证）

用户明确需求：不强制左右交替、要连续控制、要倒退。改动（PC 119 测试全绿，板端哈希核对）：

| 功能 | 行为 | 实测 |
|---|---|---|
| 前推某杆 | 该侧腿前进一步 | ✅ |
| **按住不放** | **同侧连续迈步**（左按住=绕右转）——busy 结束即重新武装，无需回中 | ✅ 连续 7 步 |
| **后拉某杆** | **该侧腿后退一步**（摆腿反向，重心转移方向不变） | ✅ |
| 双杆任何方向同推 | 冲突拒绝（含前后混合） | ✅ |
| K4 | 只做急停（用户定位：将来做攻击键，现无冲突） | ✅ |
| 提速 | 单步 1.8s → 1.33s（prepare150/wshift250/swing450/land300/stab150） | ✅ |

实现要点：
- `command_mapper`：`STEP_BACK_LEFT/RIGHT` 新事件；`_fired` 在 busy 期间清零实现"按住=连续"；回中门只在 enable/recover/link-loss 后生效（一次推拉后不再要求回中）。
- `gait_planner`：`plan_step(side, ..., backward=False)`；同侧重复不再抛异常——prepare 阶段髋收回中位（retract），支持连续同侧；`SameSideNotSupported` 已删除。
- `controller.request_step(side, backward=False)`。

## 三、幅度参数定稿（用户逐级确认）

调参过程（一次一变量）：lean 7→10→15→20→25；lift 3→5→7→10→11→10；swing 300→450ms；hip 12 被 S1 顶死边界拒绝（90-12=78 < min 82，测试当场拦截——限位测试有效）。

**最终：`hip_swing=8`（S1 物理顶死，永远不能再加）+ `lean=25` + `lift=10` + swing 450ms/land 300ms。**
- 踝限位从 65/115 放宽到 **55/125**（±35°），依据 = 9-24 现场实测 ±32/±35 两轮扫动全程顺畅（用户确认）。
- lean+lift=35 是新顶格；再大只能改机械/脚垫。
