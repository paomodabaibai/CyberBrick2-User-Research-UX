## 3. 架构（数据流即依赖方向）

```
rc 10值帧 ──input_adapter.from_rc──▶ UnifiedInput(±1标准化)
        └─ BoardSession(main_v02, 板载) ─┐
                                          ▼
                              command_mapper（事件过滤：单步触发/保持不重复/回中再武装/
                                          双推冲突/繁忙丢弃/失联去重）
                                          ▼
                              controller（DISABLED/READY/WALKING/STOPPED/FAULT 状态机）
                                          ▼
                              gait_planner（五阶段；同侧→策略接口；支撑侧策略）
                                          ▼
                              trajectory（分段+smoothstep，纯时间驱动，连续性由构造保证）
                                          ▼
                              joint_model（offset→舵机角→脉宽；超限抛异常绝不钳位）
                                          ▼
                              drivers 工厂：sim_driver（默认，只记录）| cb1_pwm（machine 懒加载，
                                          GPIO10==0 认板断言，硬跳过 left_ankle/S2 写入）
```

步态五阶段（以左脚为例，s=+1）：prepare（踝回中）→ weight_shift（双踝 s·lean 移重心）→
unload_swing（摆动踝 s·(lean+lift) 卸载）→ land（髋 s·hip 落脚，踝回中）→ stabilize（保持）。
单步 ≈1800ms（250/450/450/350/300）。

## 5. 开发过程中发现并修复的问题（供验收重点复核）

1. **simulator 日志丢失 bug**：`_log` 用 `self._pending = []` 重绑定新列表，controller 日志绑定在旧列表 append 上，导致除第一条外全部事件丢失。已改为 `del self._pending[:]` 原地清空。
2. **mapper 事件重复**：失联每 20ms 刷一条 `link_lost`、busy 丢弃每拍重复。改为每次失联只发一次、丢弃只报一次（`_link_ok` 翻转检测 + ready 消费）。
3. **controller 吞事件**：`rejected_conflict`/`dropped_busy` 由 mapper 发出但 controller 不记日志（注释错误声称已记）。已在 controller.update 统一补日志。
4. **stop_button 索引越界（测试抓到的真 bug）**：config 按 v01 习惯填全帧索引 9，而 `from_rc` 是 `frame[6 + stop_button]`，10 值帧直接 IndexError。已改为按钮组内 0 基偏移（K4→3）并在 config 注释说明。**v01/v02 索引约定不同，接手者注意。**
5. **开机摇杆已推即走（安全设计补强）**：`ENABLE_ON_FIRST_LINK` 使能帧若摇杆已前推会立即触发步态。BoardSession 初始化把 mapper 置为未武装，上电后摇杆必须先回中一次才允许触发（有专门测试）。
