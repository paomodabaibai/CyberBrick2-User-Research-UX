## 任务三：MicroPython 兼容与时间异常

**问题**：板端导入链依赖 `os.path`/`sys.path`；dt 用裸减法（回绕不安全）；无卡顿防护；步态请求会把请求前等待时间算进新动作。

**修改文件与位置**：
- `timeutil.py`（新）：板端 `ticks_ms/ticks_diff`；PC 端 30 位回绕时钟同语义。
- `drivers/__init__.py`、`drivers/cb1_pwm.py`、`main_v02.py`：移除 `os.path`/`sys.path`（板端平铺导入，不再需要路径拼接）；静态检查确认板端 12 个模块无 `os.path`、`sys.path`、`__slots__`、f-string。
- `controller.py`：dt 一律经 `timeutil.diff_ms`；dt<0 记 0；`dt > STALL_MS` 时走行中→FAULT（拒绝把丢失时间喂给轨迹，防止跳阶段/瞬移），空闲→从当前继续；`request_step` 置 `_fresh_step`，起始拍轨迹推进为 0。
- `config.py`：`STALL_MS=500`（理由写在注释：循环 20ms、最短阶段 250ms，>500ms 即丢 ≥25 拍）。
- `input_adapter.py`：删除 `__slots__`。

**行为变化**：计时回绕安全；时钟倒退不动姿态；走行中大卡顿→FAULT 且姿态不跳变；空闲大间隔无害；新步首拍 gait 时间恒为 0。

**验证方法与结果**（通过）：`tests/test_controller.py::TestTiming` 四个用例——`test_timeutil_wrap_difference`（回绕正负差）、`test_walk_across_counter_wrap_same_result`（时间戳跨 2^30 边界与不跨界的终态完全一致）、`test_negative_dt_never_moves_pose`、`test_stall_while_walking_faults_instead_of_jumping`（5000ms 间隔→FAULT、reason 含 stall、姿态与使能前相同）、`test_long_idle_then_first_step_does_not_inherit_wait`（起始拍 elapsed=0，后续每拍 20ms）。

**尚未验证项**：**静态检查完成，板端运行待验证**——无 MicroPython 环境未实测；`time.monotonic`/`ticks_*` 实际行为、导入耗时是否满足 20ms 循环需上机确认。

## 收尾一：板端"初始化 → 持续读取 → 显式使能 → 运行 → 停止/恢复 → 退出"真实可执行

**问题**：文档中的手动使能流程走不通——`start()` 只建对象不初始化遥控；`main()` 阻塞循环且 session 是局部变量，REPL 无法同时调用 `session.enable()`；`_gate()` 依赖上次保存的输入，隔久了会把旧输入当当前状态。

**修改文件与位置**：
- `main_v02.py`（整体重写）：
  - `RcLink` 类：唯一持有 `rc_module` 初始化与 `read()` 的地方。
  - `BoardSession.__init__(ctrl, cfg, link=None)`：链路作为依赖注入；`start(cfg=None, link=None)` 不再自动初始化遥控（PC 可无链路构造）。
  - `poll()`：单拍实时入口——读一帧遥控 + 控制器走一拍（REPL 分步调试用）。
  - `_live_input(action)`：**每次使能/恢复现场重读遥控**，不再读 `last_inp`；无链路/无有效帧/K4 按住均拒绝。`enable()`/`enable_debug()`/`recover()` 全部走它，并把读到的新帧喂给控制器（回中观察从真实当前杆量开始）。
  - `run()`：阻塞循环，Ctrl-C **暂停且力矩保持**，session 存入模块级 `main_v02.SESSION`，打印继续方法；`resume()` 带同一 session 重入循环；退出必须显式 `SESSION.release()`（PWM 断电）。
  - `stop()` 便捷入口；docstring 顶部写明六步完整流程与新鲜度限制。
- `README.md` / `参数说明与硬件接入清单.md`：操作流程改为真实可执行的 A（run/暂停/enable/resume/recover/release）与 B（`start(RcLink())` + 逐拍 `poll()`）两种，并保留"rc_slave_data 无序号/收包时间戳，无法识别固件缓存旧帧"的明确记录。

**行为变化**：使能与恢复不再可能基于过期输入放行；REPL 操作者按文档即可完成全过程（不再要求"测试里手工绕过入口"）；Ctrl-C 语义从"退出并断电"改为"暂停保持力矩"，避免暂停-使能-继续流程被自动断电打断。

**验证方法与结果**：`tests/test_board_loop.py` 重写为两层——`loop_once`（注入帧+时钟的纯逻辑层）与真实入口层（`FakeLink` 仿真无线模块、`FakeClock` 注入 20ms 时钟，全部走 `poll()/enable()/recover()/run()/resume()`，不绕过入口）。新集成场景：完整六步流程端到端（初始化 3 拍不动作 → 使能 → 交替两步 → K4 停止 → 失联拒恢复 → K4 按住拒恢复 → 恢复 → 回中 → 再走一步 → release 断电）；使能用的是现场读数（`read_count` 递增断言 + 存量输入后被断链仍拒绝）；恢复同门禁；`run()` Ctrl-C 暂停后 session 存活、力矩保持、`resume()` 重入；无 session 时 `resume()` 拒绝。

**尚未验证项**：板上 REPL 实际交互（mpremote 环境的 Ctrl-C 行为）未验证；`rc_module` 初始化/读取未真机跑。
