# 先读我：CB1 Otto 单步实验 v01

准备日期：2026-09-22。状态：桌面逻辑测试通过，未连接/上传/驱动实机。不能据此保证走稳。
本版保留舵机巴掌，不使用直流电机或齿轮箱。拳头电机留待后续。

## 文件
- board/milk_config.py：所有接线映射、中位、方向、限位、步幅与攻击配置。
- board/milk_probe.py：只读检查固件、遥控原始数据。
- board/milk_bench.py：单关节校准、站姿、串口单步。
- board/milk_core.py：不依赖硬件的步态与触发状态机。
- board/milk_hw.py：50Hz PWM 与巴掌控制。
- board/milk_receiver.py：利用官方 rc_module 读取已配对遥控器。
- Otto步态拆解与本版设计.md：来源、原理、偏离原版之处、待验证问题。
- tests/test_core.py：PC 测试，不是上传文件。

## 回来后第一件事：先确认程序环境
不要直接覆盖 boot.py/main.py，不要刷通用 MicroPython 固件。固件里的 rc_module 可能会因此丢失。
保留原遥控发射端程序。本版不修改配对协议。先确认原程序已配对，随后停止接收端原控制循环，不能与本版同时驱动 PWM。
准备阶段未访问任何串口；下面 PORT 要替换成实际 COM 编号。
有 mpremote 时可用：

    python -m mpremote connect list
    python -m mpremote connect PORT fs ls :

先备份板载所有现有文件（可通过 Thonny 文件面板，或 mpremote fs cp 分文件下载），特别是 boot.py、main.py、app、bbl、rc_config。记录固件版本。
若串口工具自动复位导致原程序重启，先断开执行器电源；检查 boot.py 的自动运行逻辑后再决定如何临时停用。不要盲目删除开机文件。

## 上传方式
只上传 board 里的六个 milk_*.py 文件到板载根目录；保留原文件。举例，终端先进入本地 board 目录，再逐个执行：

    python -m mpremote connect PORT fs cp milk_core.py :milk_core.py

其余五个文件同样操作。也可以用 Thonny 打开每个文件，另存到 MicroPython 设备根目录。
不要上传 reference、tests、__pycache__。不自动执行，不提供自动开机 main.py。
在已经停止官方控制循环的 MicroPython REPL 中：

    import milk_probe
    milk_probe.info()
    milk_probe.monitor(15)

monitor 只读遥控，不创建 PWM。检查推动左/右杆分别改变哪个值、静止值与方向；按按钮检查0/1。对照 milk_config.py 修改。
必须测试关闭遥控器时 rc_slave_data() 是否及时返回 None/无效数据。官方文档如此描述，但原生模块没有暴露本程序可用的新包序号；若实机一直返回缓存旧值，本版无法靠数值相同判断失联，不能启用遥控步态，需另做带序号心跳的通信方案。

## 接线建议（需要实测确认）
机器人自身的左右，不是面对机器人看到的左右：
S1 GPIO3 左髋；S2 GPIO2 右髋；S3 GPIO1 左脚踝；S4 GPIO0 右脚踝。
遥控建议 L1 左杆、R1 右杆、K1攻击、K2使能、K3停止。编号取自官方10项遥控元组，不是随意给插孔编的GPIO。
巴掌 D1 GPIO21 只是候选信号路径；接线针序、电压和第五路PWM资源验证前 ATTACK_ENABLED 保持 False。舵机电源不能接原始电池高电压；GPIO不供电。
两根杆如果不自动回中，就手动退回中间死区；本版不要求弹簧回中，但每次触发都要求回中。后拉暂不执行后退。

## 校准，先托起机器人，必要时拆开舵盘
配置默认 CALIBRATED=False、REMOTE_MAPPING_VERIFIED=False、ATTACK_ENABLED=False，导入模块不创建PWM。

    import milk_bench
    b = milk_bench.Bench()
    b.joint(0, 0)

仅左髋会收到中位命令。其他索引1右髋、2左踝、3右踝。首次上电不知道轴的真实位置，可能跳到中位；程序不能凭软件避免装错角度造成的首次跳动，所以先卸载/松开连杆或拆舵盘。
让舵机到中位，再把舵盘安装到合理机械站姿。不是用很大的 trim 去弥补舵盘错了一大格。

    b.joint(0, 3)
    b.joint(0, -3)
    b.off()

以±3°观察方向；每次最多允许±10°校准测试。b.off()停止PWM，舵机不再保证保持力，先扶住。
修改各 JOINTS 中的 center/trim/direction/min/max。direction只能填1或-1；trim通常是少量微调。
min/max是实际舵机绝对角度的机械范围；本版遇到超限会报错，不会默默截断改变步态。
修改文件后重新上传并在断开执行器电源时重启解释器，避免旧模块缓存；不要热改仍在运动的配置。
每根舵机通过、机械站姿确认后才设 CALIBRATED=True。

## 串口先走，不依赖遥控

    import milk_bench
    b = milk_bench.Bench()
    b.stance()
    b.step('left')
    b.step('right')

首步左右任选，此后必须交替；重复同侧会拒绝，不会排队。每步约1.8秒，小幅试验参数。
先观察倾斜是否让指定脚卸载；如果左脚反而压得更重，应先校正关节方向与 LEFT_SIGN，不要增加步幅强行拖动。
先扶着观察，再放地面；顶部巴掌装上后要重新验证重心。脚底材料也影响结果。
Ctrl-C 会退出动作并关闭PWM，可能失去保持力；先扶住。b.off()后再运行步态应先在托住状态调用 b.stance()。

## 遥控运行
原始通道、按钮极性和失联返回行为确认后，设 REMOTE_MAPPING_VERIFIED=True。

    import milk_receiver
    milk_receiver.run()

两杆回中、攻击松开、按住K2一秒 -> 才会给四腿发送站姿命令。首次使能仍应托住机器人。
左杆越过阈值触发一次左步，右杆对应右步。一直推住不连走；忙时的新指令丢弃，必须回中再推。
双杆同时越过阈值不动作；两杆均回中才重新解锁。
K3停止/失联超过250ms/主循环明显延迟 -> 锁存停止，腿保留最后指令，不自动回中，不接受新步态。
停止后可能停在倾斜姿态，需人扶住；Ctrl-C退出并重新运行恢复，不能自动重连就走。
退出程序会释放PWM保持力。软件停止不是物理断电开关，卡死/堵转时应使用可接近的电源开关。

## 巴掌最后启用
腿部完成验证后再单独确认第五路、焊线和供电。先不装巴掌测试。
PG001位置舵机用 position，单击一次小幅往返；ATTACK_REST_US/HIT_US独立配置。
确认是连续旋转型才用 continuous，校准 STOP_US，然后小量调整 RUN_US；按住转、松开停，另有700ms上限防止持续扫击。长按到上限后要松开重按。
攻击只在步态空闲时接受；走路时按下不会排队到落脚后自动攻击。攻击时推杆也不排队。
当前代码的攻击参数仅供卸载校准，没有验证实际75mm巴掌扫掠空间。

## 测试边界
PC自动测试仅验证触发/状态/角度范围/帧格式等逻辑，不验证真实PWM波形、无线配对、信号新鲜度、供电、舵机装配、脚底摩擦、机械干涉或稳定性。
