# CB1 串口自定义开发路线（2026-09-21）

## 当前结论
用户提供老师的非官方演示流程，拟绕开 CyberBrick 图形化功能，使用官方源码与 MicroPython 经 USB 串口开发。路线具备官方源码支持，但本项目尚未连接实机确认固件、串口、接线或运行效果。本次没有上传或运行程序。
当前目标不变：先完成一台 Otto 四舵机行走模块；巴掌、遥控协同、NFC随后分阶段验证。自定义软件不会改变舵机外形，机械适配结论继续参照打印前尺寸核对。

## 已核实的源码信息
核对提交：9712a8439f339a09e454baf543b8e97a5b1f03a7。
官方 README 说明 RC 应用可把 src/app_rc 内容上传到板载文件系统。上传脚本不等于必须刷写底层固件。在线 API 页面本次读取失败；仓库文档源文件指向同仓库 bbl 驱动的自动文档。

|用途|源码 GPIO|说明|
|---|---|---|
|舵机通道1—4|3、2、1、0|machine.PWM，50 Hz；官方位置舵机驱动可复用|
|LED通道1—2|21、20|官方用 machine.Pin 与 bitstream 驱动灯；复用为其他信号需核对电路和固件|
|电机1|4、5|电机驱动控制脚，不代表电机输出端子是裸GPIO|
|电机2|6、7|同上；驱动使用 easypwm，混用时需核对资源冲突|

以上是软件管脚编号，不是插座从左到右的针脚顺序，不能据此猜测VCC/GND。
XA005发射底板官方描述为6路ADC输入＋4路数字输入。核心具备可编程性，不代表所有输入插口均已确认可驱动执行器。

## 对老师演示说明的补充
- GPIO直驱通常指直接产生控制信号；舵机与电机供电不能来自GPIO。
- 2pin不是统一的正负电源口：可能是按钮输入、电机驱动输出或供电，必须查对应接口。
- 3/4/5/6pin数量不能判断协议或兼容性；OLED、NFC可能采用I2C/SPI/UART，需要匹配电压、协议、可用信号脚、上拉/电平转换及固件支持。
- PWM口的信号针能否改作其他功能需要核对底板线路及引脚资源。不能承诺“最多6pin外设都能接”。
- 自定义编程可以保留官方舵机、无线等可用模块，不必全部重新写。

## 对项目与物料的影响
四腿舵机：四个专用舵机口数量足够，供电能力与负载行走仍待实测。
第五个巴掌舵机：GPIO20/21所对应的灯信号路径是候选扩展方向，尚未确认可用PWM、输出电平、插口电源及并行资源。不在验证前直接接五舵机运行，也暂不认定必须多占一块主控。
NFC：优先选定一个确切模块，再核对I2C/SPI/UART与供电。保留扩展预算，不依据针脚数量采购。
六块核心板的节点规划不因开发方式自动改变：两机器人、两遥控器、两场景/备用。接收/发射底板及供电附件仍按各节点需求配置。
模型：固件路线不解决PG001与Otto舵盘、轴心、壳体配合问题，继续先一腿一脚试装。

## 首次实机开发顺序
1. 确认XA003/XA004实物、USB串口及MicroPython版本；只读检查、备份板载文件，确认恢复方式。
2. 单独测试脚本，不先覆盖开机文件；单个PG001在无机械负载下小范围动作，确认方向与中位。
3. 四舵机接入，确认供电与中位，再安装腿脚；先站立、重心摆动，后小步行走。
4. 加入遥控收发、失联停机和指令切换。
5. 单独验证第五舵机与NFC扩展，再整合攻击和游戏功能。
