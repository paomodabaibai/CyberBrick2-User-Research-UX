# milk组桌面双足对战机器人｜六周执行路线图

版本：2026-09-23。项目目录：`E:\课程作业\大三上\张茫 用户研究与体验设计`。
面向组员和接手Agent。时间是滚动六周建议，课程最终交付日期尚未确认；以每阶段通过标准决定是否进入下一阶段，不以日历日期冒充完成。

## 0. 最终要交付什么
两台约10–20cm Otto V9 短腿机器人、两个遥控端、可说明且可重复的对战规则，以及记录了用户体验与迭代过程的课程展示材料。首台巴掌款优先；第二台对战机优先具备同等行走与交互能力，Punchy拳头是后续攻击模块目标。NFC技能卡与场景道具为可选扩展。

最低可用版本（MVP）：第一台能按左杆/右杆分别完成左右单步，左右交替可停可续；K4能停止；掉线不自动续走。第二台能以同样方式移动并与第一台做短局对战；攻击功能至少一台巴掌款可触发，碰撞轻量可控。若最终无法可靠实现双机，应如实展示单机可用交互和经验证的技术边界，不能伪造对战完成。

四种证据等级必须分开：①PC自动测试；②板端命令/日志；③观察者确认关节动作；④机器人真实站稳、移动或击倒。任何报告标注对应等级。

## 2. 执行原则与决策顺序
主线依赖：四舵机正确装配 → 站姿 → 移重心 → 单步 → 双杆连步 → 攻击 → 第二台 → 对战体验 → 展示。先保证前一步可复现再叠加重量和变量。
每次实机试验只变一个参数组；先记基线，再记修改，再记录观察。明确“电气90°”不等于舵盘外观相同；错误齿位应重装，不用大trim补偿。
PC/资料任务可在用户离开时执行。任何会使实机运动的步骤，应由用户在场观察、机器人受支撑，且物理断电开关可及。暂停的软件循环不具备K4/失联轮询保护；短测优先用有确定时长和finally关闭PWM的脚本。
本计划中成员分工为建议，未替四位成员擅自指派。组内确定负责人后把姓名填入任务表。

## 3. 六周滚动时间表

### 第1周：已完成的定位与准备（9月16日所在周，记录为历史）
成果：提案汇报、Otto/Punchy参考、初版硬件需求、巴掌模型与打印包、CB1迁移。不要重复做提案PPT。未完成的打印件试装和真实负载检查移到后续阶段。

### 第2周：一台机器人建立可重复站姿（9月23日所在周，当前最高优先级）
**可马上独立完成**
1. 修对中工具“切换一路先关上一路”和“定时发送被中断仍关PWM”，加两项失败先行测试。核查`center_joint.send()`默认90°、配置的PG002拒绝策略、板端导入无动作。完成后复跑全量测试，记录新数量。
2. 核对四个舵机实物型号/数量，明确待换S2的180° PG001来源；记录舵盘、螺钉、CB1专用线、电池、物理开关库存。只有真实到手才写“具备”。
3. 把安装图与Otto V9原装配手册的照片页人工对照；任何无法确定的轴向标“待现场核对”，不要写成手册已证实。
4. 准备单关节现场记录表与文件/板端哈希记录；新脚本上传只限接收板，不改变发射端。
**用户在场后**
5. 完成B3：逐个托住观察右髋、左髋、右踝±3–5°动作；确认通道、方向、无顶死；S2保持禁用。完整暂停/使能/停止/恢复/释放流程只在明确输出状态下测。
6. 四只180°位置舵机齐备后进行C：拆开受力连接，逐路发电气中位，重装舵盘/腿脚，微调；逐路记录型号、角度、方向、安全范围，用户观察后才设`calibrated=True`。
7. 四路校准完托住发站姿，再短时桌面落地。只验收双脚平放、机身不明显倾斜、没有持续顶死/抖动；本周不以能走路作为对中通过条件。
**关口C**：四关节都是可定位舵机；接口映射、方向、中位、安全范围有表；双脚站姿有正/侧照片和观察确认。若未通过，继续机械对中，不运行完整步态。

### 第3周：第一台单步与双杆行走
1. 无攻击模块或使用等重假负载，先测原机重心。托住做最小幅度移重心，明确左步时真实支撑脚是哪只；核对`step_sign_left/right`和`ankle_sign`。
2. 串口分别执行左单步、右单步。每次视频记录五阶段；观察目标脚是否卸载、是否拖脚、落脚是否稳。先在受支撑状态，再落地。
3. 参数顺序：关节中位/方向 → `lean` → `lift` → `hip_swing` → 各阶段时间。一次只改一种；若动作“完成”但位移近零，先判断脚底摩擦、重心和结构自由度，再改角度。
4. 达到单步后接入遥控：左杆触发左脚一步，右杆触发右脚一步，长推不重复、回中再触发、双杆冲突忽略、K4停止、掉线故障。第一轮只做左右交替；同侧重复明确拒绝。
5. 设立小型重复试验：至少3个独立回合，每回合左/右交替各5步；每步记录成功/拖脚/倒地。**建议门槛**：有至少2回合能完成5次交替且可停顿；同时记录桌面位移，数值由实测得出，不先编目标厘米数。若不达标，回到单步调参。
**关口D/E**：观察者确认指定脚在行动、回中可再次触发、停止与失联表现符合设计；视频与参数版本归档。

### 第4周：巴掌模块与第一台整机整合
1. 试装75mm手掌、51mm杆距、腕块、顶部框和舵机桥；核对M2×8根部两颗、M2×25横穿一颗及三颗螺母，确认不会松脱，扫掠范围无碰线/碰头壳。
2. 确定巴掌舵机类型：PG001位置型可做有限角往返；PG002连续型只可控制方向/速度与停转，不能凭90°命令回到固定起点。根据真实零件选一种并记录控制策略，不把两种代码混用。
3. 核对第五路D1/GPIO21的真实信号线序、电源轨与同时驱动五舵机的供电。先卸下手掌只测舵机，再装轻质手掌，最后按空载→对柔软目标顺序试动作。任何明显掉压复位或卡住，暂停并改供电/机构。
4. 把巴掌重量装上后重新验证站姿和10步交替；重心可能改变，第3周参数不能直接视作仍有效。
5. 加攻击互斥：站稳时可触发，迈步时不排队；K4始终优先。当前遥控只有一个实体K4且作为停止，**攻击键不可默认为已具备**；需增设按钮或明确替代输入映射后再做操作整合。
**关口F**：巴掌空挥可重复且不松脱；整机带攻击模块仍能满足上一周的基本连步门槛；攻击与停机互不冲突。若无法完成第五路，先展示可靠行走与手动触发巴掌台架，不伪称无线攻击已完成。

### 第5周：第二台、拳头探索与玩法体验
1. 按第一台最终确认的机械/电气/软件版本复制第二台；建立独立配置文件和序列号/遥控配对记录。不要仅复制STL就假定重心/trim相同，第二台四关节需单独标定。
2. 优先把第二台做成“能稳定走、能停”的对战体。若资源足够，再以Punchy.stp为参考设计拳头上部：检查目标尺度、曲柄/连杆行程、电机/减速箱、输出轴支撑、安装座和碰撞空间。现有LA016是1:48单轴减速齿轮包，是否适配Punchy尚未证明，需先台架验证。
3. 定简版游戏规则：一局时长、场地边界、何为倒地、击倒判胜、卡住/断线暂停、人工扶正与重赛。用纸面规则跑至少2次双人短局；记录“操作是否能理解”“输赢是否有争议”“碰撞是否太弱/太强”。
4. 做短访谈/观察记录，至少覆盖两名未参与制作的试玩者。记录原话、卡住的操作与改动理由，不能把小组自己的想法当用户调研结论。
**关口G**：第二台能按同一规则完成移动与停止；至少一场有记录的双机短局。拳头若未过台架关口，降级为展示结构原型，不阻塞双机对战。

### 第6周：稳定性、课程体验和最终展示
1. 做至少3轮完整对战与一次故障演练（掉线、卡住、舵机未回中），记录实际恢复步骤与失效点。调整游戏时长/场地/规则，不在最后一周大改底层步态。
2. 整理“从最初概念到可玩原型”的证据：早期用户需求、Otto机构选型、结构迭代、代码状态机、实机标定表、失败/修复、试玩反馈。照片与概念图需明确标注。
3. 准备现场演示脚本：上电前检查→站姿→左右杆走步→攻击→K4停→短局→故障恢复；准备一份无网络的本地视频与图片备份。演示时的真实效果仅展示已通过的动作。
4. 备好可复现交付包：最终代码与配置、STL/STEP、打印/装配说明、硬件BOM及实际数量、遥控映射、玩法规则、测试表、视频、PPT。检查文件能打开、链接正确、图示与实物一致。
5. NFC/技能卡仅在主线连续可用且仍有时间时开启独立小试验。NFC所需接口、电源、读卡距离和双机同步规则未验证；若任何一项阻塞，作为未来扩展陈述。
**关口H**：一次从冷启动到完成短局的演示可重复；文档可让新组员按步骤恢复系统；PPT只主张已有证据支持的结果。

## 4. 每阶段的角色与工作方式
建议四条责任线（组员自行确定负责人）：
- **结构与装配**：舵机型号核对、舵盘重装、支架、巴掌/拳头装配、照片、打印件版本。
- **电气与供电**：CB1接口/线序、供电电压与掉压观察、开关、遥控配对、故障记录。
- **控制与测试**：v02配置、台架脚本、步态版本、自动测试、实机录像对照、回滚包。
- **体验与展示**：游戏规则、试玩招募/观察、体验改动、演示脚本、PPT与视频。
每次实机试验最好两人：一人操作/可断电，一人观察并记动作。四类证据等级写在记录首行。

## 5. 每次试验统一记录模板
记录一行即可追踪：
`日期时间 | 机器人/板卡序列 | 代码与config版本 | 接线与舵机型号 | 地面/负载 | 目标动作 | 实际观察 | 视频/照片路径 | 是否通过 | 下一改动`。
参数变化另记“旧值→新值→为什么改”。出现异常先保存输出与配置，再根据症状定位，不边试边连改多个值。
建议统一保存至`05_程序与测试/实机试验日志_YYYY-MM-DD.md`，相应录像放`03_视觉素材/实机记录/`。最终版本单独复制到`05_程序与测试/发布版/`，不要覆盖试验版本。

## 6. 决策点与降级路线
- **第2周末还缺180°左踝**：完成三路台架及遥控/失联流程，继续等件；不让连续旋转舵机参与完整步态。
- **第3周末有四舵机但无法稳定单步**：先验明四路机械中位和物理轴方向，再分开测试移重心和摆髋；可调整脚底摩擦/重心或模型，不能只无限增大角度。保存“原因未证实”结论。
- **第4周末第五路供电/连接不稳**：保持第一台行走，巴掌独立台架展示；第二台与规则推进不必等待攻击模块。
- **第5周末Punchy难以缩小或驱动不足**：第二台先沿用已验证的简单攻击机构或仅保留移动对战；Punchy作为结构验证件。不得把未验证的拳击称为成品。
- **第二台资源不足**：明确硬件缺口，优先完成一台可交互机器人和双人轮换操控体验；最终展示据实说明未实现双机同时对战。
每周一次15分钟关口检查：看现场证据、列未过项、确定下周唯一最高优先级。用户画像/NFC/视觉包装不能抢占站姿、步态和供电问题的资源。

## 7. 接手Agent的第一批可执行任务
无需用户在场：
1. 重读`PROJECT_CONTEXT.md`和最新实测记录，核对当前代码/板端版本，不以旧交接的“马上继续”作为唯一依据。
2. 修复对中工具的两项PWM清理缺口，补测试并复跑全量；修正“95项”数字与结果存档。若改了上传白名单/文件数量，同步台架计划。
3. 人工核对Otto V9手册照片与四关节安装图；不确定处保留推断标签，避免具体错误角度引导装配。
4. 做一页硬件现货清单：四个腿部180°位置舵机的实收数量、遥控按钮数量、第五路所需线和电源、第二台的缺口。未知填“未核对”，不当作已经采购。
5. 把第2周阶段C的现场步骤写成一页顺序卡，方便用户到场按关节逐个操作。
完成后交付：代码差异、测试结果、安装图核对结论、硬件缺口、下次实机测试清单。除这些软件/资料工作外，不在用户不便观察时驱动机器人。

## 8. 对外汇报口径
目前已证实：遥控两杆与K4输入、关遥控返回None、接收板启动无PWM、已上传主框架且只读诊断正常。尚未证实：四腿机械对中、真实四关节站姿/步态、第五舵机/攻击、双机对战。之前“95项测试全绿”仅是PC逻辑验证。
