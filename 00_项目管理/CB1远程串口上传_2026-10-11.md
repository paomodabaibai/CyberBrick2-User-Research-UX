# CB1 远程串口上传

另一台电脑接着 CyberBrick 1 接收板/发射板时，可以由本机通过 SSH 操作它的 USB 串口。所附《REMOTE_SERIAL_SSH_COMPLETE_GUIDE.md》提供了远程电脑的现场信息；其中的 ESP32 固件刷写、Arduino 等命令只是通用模板。本项目已使用 MicroPython 和 `mpremote` 上传 `.py` 文件，**不要用 esptool 的整片固件刷写命令替代**。

- 附件记录的远程主机为 `windows11@192.168.1.107`，串口有 COM6、COM9，但两者与实体板的对应关系尚未确认。
- 本机现在用 `WLAN 2: 183.173.180.100`，不在远程电脑的 `192.168.1.0/24` 局域网。2026-10-11 连接远程 22 端口超时；远程上传**尚未端到端验证**。两机须在同一局域网，或先接入彼此互通的 VPN；也要检查远程电脑 IP 是否已变化。
- 本机有 Tailscale，但当前设备列表里没有远程 Windows 电脑。若两地工作，可以让远程电脑接入同一个 tailnet，再将下文的 `-HostName` 改成它的 Tailscale IP。

## 远程电脑准备一次

1. 确认 `sshd` 正在运行、两机网络可互通，并确认远程电脑当前 IP。
2. 安装 `mpremote`：`py -m pip install mpremote`；在远程 PowerShell 用 `mpremote --help` 验证能调用。不要在这里安装整片固件刷写工具。
3. 为本机配置 SSH 登录。推荐密钥；远程用户若属 Administrators 组，Windows OpenSSH 可能要求把公钥放进 `C:\ProgramData\ssh\administrators_authorized_keys`，而非个人 `authorized_keys`。按远程主机实际配置为准。不要把私钥提交 GitHub。
4. 通过拔插或板端只读身份探针确认 COM6/COM9 哪一个是接收板。接收板 GPIO10 读数为 0；上传助手也会在写入前核验。串口号可能随重插变化。

## 本机调用

先在项目根目录执行只读探针（此命令不会上传）：

```powershell
& '.\05_程序与测试\CB1_Otto控制框架_v02\远程上传CB1脚本.ps1' -HostName 192.168.1.107
```

确认接收板串口后，将一个 MicroPython 脚本上传到它的同名文件，不会自动运行：

```powershell
& '.\05_程序与测试\CB1_Otto控制框架_v02\远程上传CB1脚本.ps1' `
  -HostName 192.168.1.107 -Port COM6 `
  -FilePath '.\05_程序与测试\CB1_Otto控制框架_v02\hold_90_cb1.py'
```

如需上传后立刻 `import` 脚本，可加 `-Run`；`main.py` 和 `boot.py` 不支持这个开关，避免误触发自启动。现有完整步态涉及多文件依赖与板上/PC 两种 `config.py`，应按项目既有上传清单一次核对，不要只上传单个入口文件覆盖运行环境。

远程电脑可从 GitHub 拉取完整项目，也可由助手经 SCP 只传本次脚本。SSH、SCP 和 `mpremote` 任一步失败，助手会停止并报告；真正的机械动作仍需现场人员观察。
